# Persona-specific first emails. Each lead gets ONE of the templates below
# instead of the single email_template.txt everyone used to get - the AI
# picks whichever one genuinely fits, based on the lead's job_title column
# and what its company's own website says (see company_research), then
# fills in that template's {{ }} blanks. Same rules as email_template.txt:
#   {{company}}, {{email}}, {{contact_name}} - plain find-and-replace, no
#     AI. contact_name comes from the leads table's contact_name column -
#     if it's blank for a lead, "{{contact_name}}," in a greeting collapses
#     to "," automatically so it never reads as "Hi ,".
#   anything else inside {{ }} - a short instruction, filled in by the AI
#     for that one spot only.
#
# Every persona block below MUST:
#   - start with a label line ending in ":" (this is what gets matched
#     against the lead's job_title/industry - make it specific)
#   - have a "SUBJECT:" line right after it (can itself be a {{ }} blank,
#     like the ones below)
#   - be separated from the next persona by a line containing only ---
#
# A lead whose job_title is blank, or doesn't clearly match any persona
# below, does NOT fall back to company_email_templete.txt - personal_emails
# rows only ever get a persona email. Instead that lead is marked
# needs_attention and you get an alert email, so you can add/adjust a
# persona (or fill in job_title) and flip it back to "new" to retry.
# Add as many personas below as you want; there's no limit.
#
# Each persona's "superhuman" line (see below) can now draw on BOTH
# linkedin_info AND, if this lead has a company_website on file, an
# automatic scrape+summary of that company's own site (cached into
# company_research) - the AI is given both together when filling blanks.
#
# Every persona below opens with one "superhuman" personalization line
# right after the greeting - two {{ }} blanks filled from that lead's own
# company_research, in this exact shape:
#   קראתי עליכם קצת וראיתי שהלקוחות שלכם הם {{...}}. אני בלומנה פותר את
#   הבעיה הזו בזה שאני {{...}}.
# If you add more personas of your own, copy that same line in - it's what
# makes the email feel like it was actually read and written for THIS
# company rather than templated. Like every other blank, it's skipped
# (both sentences together) if the research doesn't give the model enough
# to say something real and specific - never a vague filler guess.
#
# --------------------------------------------------------------------------
# WRITING RULES for anyone adding/editing a persona below (enforced partly
# by outreach_bot.py's find_style_violation() as a code-level backstop, on
# top of being spelled out to the model in FIRST_EMAIL_PERSONA_SYSTEM -
# see the code for both):
#   1. FIXED ORDER: (a) company-specific fact - only the {{ }} blank above,
#      skipped entirely if there's nothing real to say, never invented;
#      (b) one universal pain sentence, phrased as a general truth about
#      this KIND of company - never a specific claim about the recipient
#      you can't verify; (c) the one-line self-intro ("אני מנהל מכירות
#      לומאנה בצוות 3") - never before (a)/(b); (d) exactly ONE concrete
#      capability, chosen from the site-type table below - never two, and
#      never invented for a site type that isn't in the table (use the
#      generic "לאתר רגע ספציפי בשפה חופשית" line alone instead - see the
#      hotel and HR personas below for examples of that); (e) a closing
#      {{ }} blank that picks EXACTLY ONE of three fixed closing-line
#      options and copies it word for word (see CLOSING LINE below) - this
#      is the one deliberate exception to the "no dash / no rhetorical
#      question" rule right below, since it's the one thing we're
#      deliberately asking the model to copy rather than write itself.
#   2. HARD NOs, anywhere in the fixed body text OR a blank (EXCEPT the
#      closing-line blank, which is exempt - see above):
#        - no dash characters (- or ־) anywhere at all
#        - no rhetorical question as the opening line
#        - no assuming infrastructure that hasn't actually been confirmed
#          for THIS lead (e.g. "your street cameras", "your existing
#          control room", a specific incident count)
#        - never belittle their existing equipment ("your dumb camera",
#          etc.)
#        - never name a Lumana client or award inside a cold first email -
#          that needs separate approval every time it's used
#        - never claim a specific prior interaction with THIS company
#          (e.g. "we already connected to your camera") unless it's
#          actually true and verified
#        - at most one concrete capability per email (see the table)
#
#   SITE-TYPE -> CAPABILITY TABLE (pick the one row that matches, mention
#   ONLY that capability - never more than one):
#     factory / construction / industrial site  -> missing safety gear
#       (helmet/vest) detection
#     warehouse / logistics / courier site       -> unauthorized person
#       entering the warehouse outside operating hours
#     mall / municipality / parking lot          -> vandalism, or a
#       suspicious vehicle returning to the site
#     sensitive security site                    -> weapon near a secured
#       area
#   No matching row for a persona's site type (hotels, HR, and anything
#   else not listed above)? Don't invent a specific capability - keep that
#   persona's pitch to the generic "search any moment in plain language in
#   seconds" line only, same as the hotel and HR personas below.
#
#   CLOSING LINE: every persona below ends on the same {{ }} blank, and its
#   instruction is identical in all 4 - the model must pick EXACTLY ONE of
#   these three fixed options and copy it word for word, not paraphrase it
#   or blend two of them together (enforced by outreach_bot.py's
#   find_closer_violation() as a code-level backstop, with one retry before
#   falling back to needs_attention):
#     1. "אשמח להראות ב-15 דקות איך זה נראה בול על המצלמות שלכם – כמה זמן
#        חיפוש בהקלטות זה חוסך בפועל, ואיך נראית התראה בזמן אמת במקום
#        לגלות אירוע רק למחרת. נוכל לתאם שיחה קצרה?"
#     2. "יש לי דרך פשוטה להראות לצוות שלכם איך זה עובד בזמן אמת ובמה זה
#        מחליף סריקה ידנית של שעות הקלטה בכל אירוע. שווה 15 דקות שיחה?"
#     3. "אשמח להראות בשיחה קצרה בדיוק איך זה עובד על המקרה שלכם – מה זה
#        חוסך בזמן טיפול באירועים, ואיך ההתראות בזמן אמת מונעות את הבעיה
#        הבאה לפני שהיא קורה. מתאים שנקבע רבע שעה?"
#   If you add a persona of your own, copy the SAME closing blank in
#   (identical instruction text) rather than inventing a new closing line -
#   see any persona below for the exact wording to copy.
# --------------------------------------------------------------------------
